# Demo walkthrough video

End-to-end automated walkthrough of the live AgroConnect PWA at
`https://app.agroconnect.space`, recorded via Playwright, stitched with ffmpeg.
The output file (`agroconnect-demo.mp4`) is the artifact used in the lab viva
presentation.

## Watch

```
open agroconnect-demo.mp4
```

Current build: **159 s · 1280×720 · 30 fps · H.264 · 1.6 MB**. No audio
(intentionally — reviewers can narrate live during the viva).

## What the video shows (in order)

| Section | Role | Account | What happens |
|---|---|---|---|
| Intro title | — | — | Project name + live URL |
| Farmer | farmer | `0200000010` / PIN `1234` | Role picker → sign-in → Market with trend arrows + currency picker → Wallet (test-mode pay attempt) → Advice → Me |
| Agent | agent | `AG-0001` / password + first-time PIN | Home gauge → Register (3-step: Who / Farm / Proof with GPS + photo + consent) → Farmers list → sign-out → pending agent `+233200000099` seeing "Waiting for approval" |
| Admin | admin | `ADM-001` / password + first-time PIN | Dashboard → Agents queue (approves the pending agent) → Coordinators view (opens "Add a coordinator" sheet) → Activity (audit log with real farmer-insert events from the agent flow above) → back to Overview |
| Coordinator | coordinator | `CO-001` / password + first-time PIN | Home → Stats → Farmers → More |
| Outro title | — | — | End card |

**Deliberately skipped** (noted here so reviewers aren't surprised):
- Wallet payment success path → requires the votex365 checkout popup; the "Saved…" state is shown instead.
- Admin's actual coordinator-creation submit → would create a new coordinator every run; the sheet is opened and cancelled.
- Crop-check write + answer round-trip → needs two signed-in roles concurrently.

## Rebuild from scratch

```
cd scripts/demo-video
npm install                 # one-time; installs Playwright
npx playwright install chromium
./build-video.sh            # runs tests + ffmpeg concat → ~2.5 min
```

Output: `agroconnect-demo.mp4` is overwritten.

## Known fragilities (so the next person to re-run isn't surprised)

- **All role specs must run in a single Playwright invocation.** `build-video.sh`
  does this. Running them separately wipes `test-results/` between runs.
- **Scroll overlay on bottom nav**: a `<ul class="plain-list">` sometimes
  intercepts pointer events on the bottom-nav icons. The specs use
  `click({ force: true })` to work around this. If a selector starts failing,
  that's usually why.
- **Live backend**: the video records against production. The demo accounts are
  seeded by `backend/src/seed.ts` and expected to exist. If someone resets the
  DB, re-seed before re-recording.
- **Audit log entries are real**: each full run creates a few farmer records
  under `AG-0001` and leaves them in the DB. This is intentional — the admin
  Activity screen then shows them, which proves the end-to-end persistence.
  Over months, if the DB fills with demo farmers, prune by `clientId` prefix.
